# シングルモード

一台のタブレットを2〜4人で使い、QRカードで命令を組んでロボットを迷路のゴールまで動かすモードです。
児童はチュートリアルを順番に解き、すべてクリアした後に自分で迷路を作ります。教師は児童ごとの進み具合を一覧で確認します。

このディレクトリの仕様書は、バイブコーディングで実装するときにAIへ渡す前提で書いています。

| ファイル                  | 内容                                         |
| ------------------------- | -------------------------------------------- |
| README.md（このファイル） | 画面、画面遷移、文言のルール                 |
| [domain.md](domain.md)    | 迷路・命令カード・実行ルール・チュートリアル |
| [backend.md](backend.md)  | データモデル・API・アクセス制御・性能の方針  |
| [plan.md](plan.md)        | 実装の順序とタスク                           |

## 決定事項

| 項目             | 決定                                                                                                                                                                                             |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 対象範囲         | シングルモードのみ。ペアモードは後回し                                                                                                                                                           |
| 児童の識別       | 授業QRを読み取った後にニックネームを入力する。端末には児童のトークン（ランダムな文字列）を保存する。トークンが消えた児童が同じ名前で参加し直しても、新しい児童として扱い、前の記録は引き継がない |
| 教師の識別       | ログインなし。最初の訪問時に教師のトークンを発行してブラウザに保存する。そのトークンで作った授業だけを見られる                                                                                   |
| 命令カード       | 前にすすむ、右にまがる、左にまがる、穴をうめる、くりかえす（回数は画面で2〜10に決める）、くりかえし終わり。6種類をKASANEで新しく印刷する                                                         |
| 通信の構成       | 教師1人と児童N人が、それぞれサーバーとだけ通信する。状態を変える操作はすべてHTTP、サーバーからの知らせだけをSSEで受け取る                                                                        |
| 授業の終わり     | 教師の「授業を終える」で終わる。押し忘れたときは作成から5時間で自動的に終わる。終わったら教師と全児童の画面がすぐ切り替わる                                                                      |
| プログラムの形   | 読み取ったカードは、その場で木構造（`Program`）に差し込む。端末は木構造を直接編集し、「ロボットを動かす」でそのまま送る                                                                          |
| コンパイル       | 児童が送った木構造を、サーバーが`packages/core`の純粋関数で各ターンの位置に変換し、送った児童に返す。教師には成功・失敗から求めた状態だけを送る                                                  |
| 迷路の形         | 一辺5〜7マスの正方形を1〜3階重ねる。マスは床・壁・穴・スタート・ゴール・上へテレポート・下へテレポート・鍵の8種類                                                                                |
| 保存するもの     | 1回送るごとに「どの迷路か・プログラム（木構造）・成功したか・送った時刻」。コンパイル後の位置は保存しない                                                                                        |
| 教師に見せる状態 | 児童ごとに「チュートリアルの何問目/全体（または全部クリア）」と「今の問題の結果（まだ送っていない/成功/失敗）」                                                                                  |
| 自分の迷路の公開 | 自分の迷路だけを遊べる。他の児童との共有は後回し                                                                                                                                                 |

## 文言のルール

- 児童画面は、小学6年生までに習う漢字だけを使い、漢字にはすべてルビを振る（漢字の上に読みを置く）。教師画面はルビを振らない（どちらも、ITに慣れていない人が読む前提）。ルビはReactの部品で描き、HTML文字列にしない（[backend.md](backend.md#トークン)）
- 仕様書の児童向け文言は`<ruby>迷路<rt>めいろ</rt></ruby>`の形で書く（GitHubでそのまま漢字の上に読みが出る）。実装も同じ要素に対応させる
- ルビのぶんだけ行が高くなるので、ボタン・入力欄・カードの高さと余白はルビ込みの行の高さで決める。部品の既定の余白に任せると、ルビが上の余白にはみ出して崩れる
- 「何を」「どうする」を省略しない。ボタンは動詞で終える（例:「プログラムを<ruby>直<rt>なお</rt></ruby>す」「<ruby>次<rt>つぎ</rt></ruby>の<ruby>問題<rt>もんだい</rt></ruby>に<ruby>進<rt>すす</rt></ruby>む」）
- 失敗の表示は「何が起きたか」と「次にどうするか」を必ずセットにする
- 文言は画面側で決める。サーバーは状態とコード（例:`410`と`lessonEnded`）だけを返すので、同じコードでも児童画面と教師画面で相手に合わせた言葉にする
- 「ルーム」「トークン」「セッション」「ロード」「エラー」など開発者向けの言葉は画面に出さない
- 日本語と英数字の間にスペースを入れない
- 強調は文言（「！」の多用、「重要」など）ではなく、形・色・動きで行う

## 見た目と操作のルール

- 基調は青と白。教育の道具として誠実さと信頼感を伝える色にする。児童画面は、その中で「学んでいて分かりやすい」ことをより強く出す
- フォントは、児童画面・教師画面ともにユニバーサルデザイン書体のBIZ UDPGothic（[architecture.md](../../architecture.md)）
- 画面上部の「もどる」は、棒のない「＜」の形の矢印ボタンで、どの画面でも同じ
- 一画面一目的。画面の中で一番大きく、色がついたボタンは一つだけにする
- 児童画面のタップできる部分は最低64px四方、文字は最低20px
- 状態は色だけで伝えず、必ずアイコンや形も添える（色覚の多様性への配慮）
- 児童画面の動き（アニメーション）は、ロボットの移動・カードを読み取ったとき・次に押すボタンの3か所に絞る。教師画面はこの制限の外（QR画面で参加した人数が弾む動きなど）
- 共通UIコンポーネントは、2画面以上で同じものが必要になったときだけ作る

## 画面遷移

### 児童（apps/student）

```
[先生のQRを読みとる] ──→ [ニックネームを入れる] ──→ [ホーム]
                                                 │
                     ┌───────────────────────────┤
                     ↓                           ↓
            [もんだいのしょうさい]       [じぶんのめいろのしょうさい] ←── [めいろをつくる/変える]
                     │ あそぶ                    │ あそぶ  │ 変える
                     ↓                           ↓         └──────→ [めいろをつくる/変える]
              [プレイ: プログラムをつくる] ⇄ [プレイ: ロボットを動かす]
                                                 │ クリア
                                                 ↓
                                     つぎのもんだい / ホーム
```

| ルート                | 画面                       | 目的                                           |
| --------------------- | -------------------------- | ---------------------------------------------- |
| `/join`               | 授業に参加する             | 授業QRを読み取り、ニックネームを入れて参加する |
| `/`                   | ホーム                     | 遊ぶ迷路を選ぶ                                 |
| `/tutorials/$no`      | もんだいのしょうさい       | 迷路の形を3Dで確かめる                         |
| `/tutorials/$no/play` | プレイ                     | プログラムを作って動かす                       |
| `/mazes/new`          | めいろをつくる             | 新しい迷路を作る                               |
| `/mazes/$mazeId`      | じぶんのめいろのしょうさい | 迷路の形を3Dで確かめ、遊ぶか変えるか消すか選ぶ |
| `/mazes/$mazeId/edit` | めいろを変える             | 迷路を作りかえる                               |
| `/mazes/$mazeId/play` | プレイ                     | プログラムを作って動かす                       |
| `/ended`              | 授業がおわりました         | 授業が終わったことを伝える                     |

児童のトークンが端末にないとき、どのルートでも`/join`へ移動します。授業が終わっていたら`/ended`へ移動します。
`/join`と`/ended`以外の児童の画面は、一つのパスなしレイアウト（TanStack Routerの`_`で始まるルート）の下に置き、そのレイアウトで`GET /me/events`に一つだけつなぎます。画面を移っても接続は持ち越します。つなげないとき（`401`）は`/join`へ、始まる前から終わっていたとき（`410`）は`/ended`へ移動します。
授業中に先生が授業を終えたら、どの画面にいても、すぐ`/ended`へ移動します（SSEで`ended`を受け取る）。通信が切れていて知らせを受け取れなかった端末も、次に操作したときに`/ended`へ移動します。

### 教師（apps/teacher）

```
[ホーム] ──授業を始める──→ [QRコードを見せる] ──→ [進み具合]
   │                              ↑                    │
   └──開いている授業を選ぶ────────┼──────────────────→│
                                  └──QRコードをもう一度表示する
```

| ルート                      | 画面             | 目的                               |
| --------------------------- | ---------------- | ---------------------------------- |
| `/`                         | ホーム           | 授業を始める・開いている授業を選ぶ |
| `/lessons/$lessonId/invite` | QRコードを見せる | 児童に授業へ参加してもらう         |
| `/lessons/$lessonId`        | 進み具合         | 支援が必要な児童を見つける         |

## 児童の画面

### 授業に参加する（`/join`）

1. `?lesson=`がないとき: カメラ映像を大きく表示し「<ruby>先生<rt>せんせい</rt></ruby>の<ruby>画面<rt>がめん</rt></ruby>のQRコードを<ruby>写<rt>うつ</rt></ruby>してください」と出す
   - 授業QRには`{STUDENT_ORIGIN}/join?lesson={授業のID}`のURLが入っている。タブレットのカメラアプリで読み取っても、この画面のカメラで読み取っても同じ画面に来る
2. `?lesson=`があるとき: ニックネームの入力欄と「この<ruby>名前<rt>なまえ</rt></ruby>で<ruby>始<rt>はじ</rt></ruby>める」ボタンを出す
   - 入力欄の上に「ニックネームを<ruby>入<rt>い</rt></ruby>れてね」、下に小さく「<ruby>自分<rt>じぶん</rt></ruby>の<ruby>本当<rt>ほんとう</rt></ruby>の<ruby>名前<rt>なまえ</rt></ruby>は<ruby>入<rt>い</rt></ruby>れないでね」
   - 1〜20文字。空のときはボタンを押せない（灰色）
3. 参加できたら児童のトークンを`localStorage`に保存し、ホームへ移動する

失敗時の表示:

| 状況                             | 表示                                                                                                                                                                                                                   |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 授業のIDが正しくない             | 「このQRコードでは<ruby>参加<rt>さんか</rt></ruby>できません。<ruby>先生<rt>せんせい</rt></ruby>の<ruby>画面<rt>がめん</rt></ruby>のQRコードをもう<ruby>一度<rt>いちど</rt></ruby><ruby>写<rt>うつ</rt></ruby>してね」 |
| 授業が終わっている               | 「この<ruby>授業<rt>じゅぎょう</rt></ruby>は<ruby>終<rt>お</rt></ruby>わっています。<ruby>先生<rt>せんせい</rt></ruby>に<ruby>聞<rt>き</rt></ruby>いてね」                                                             |
| 授業の児童の数が上限に達している | 「この<ruby>授業<rt>じゅぎょう</rt></ruby>にはこれ<ruby>以上<rt>いじょう</rt></ruby><ruby>参加<rt>さんか</rt></ruby>できません。<ruby>先生<rt>せんせい</rt></ruby>に<ruby>聞<rt>き</rt></ruby>いてね」                 |
| 通信できない                     | 「インターネットにつながっていません。もう<ruby>一度<rt>いちど</rt></ruby>おしてね」＋「もう<ruby>一度<rt>いちど</rt></ruby>」ボタン                                                                                   |

### ホーム（`/`）

- 上部: 名前
- 「<ruby>問題<rt>もんだい</rt></ruby>」: チュートリアルをカードで横に並べる（番号が大きく見える）
  - クリア済み: 星のアイコン＋塗りつぶし
  - 次に解く問題: 色つき＋ゆっくり拡大縮小する動き（ここだけ動かす）
  - まだ解けない問題: 灰色＋鍵のアイコン、押せない
- 「<ruby>自分<rt>じぶん</rt></ruby>の<ruby>迷路<rt>めいろ</rt></ruby>」: 自分が作った迷路の一覧と「<ruby>新<rt>あたら</rt></ruby>しい<ruby>迷路<rt>めいろ</rt></ruby>を<ruby>作<rt>つく</rt></ruby>る」ボタン
  - チュートリアルをすべてクリアするまでは灰色＋鍵のアイコン、下に「<ruby>問題<rt>もんだい</rt></ruby>を<ruby>全部<rt>ぜんぶ</rt></ruby>クリアすると<ruby>作<rt>つく</rt></ruby>れるよ」。この間は一覧を取りに行かない（`canCreateMaze(clearedCount)`が真になってから`GET /me/mazes`を呼ぶ）
  - 一覧は更新が新しい順（左上から右下へ）
  - 迷路が一つもないときは「まだ<ruby>迷路<rt>めいろ</rt></ruby>がないよ。<ruby>作<rt>つく</rt></ruby>ってみよう」と出す
  - すべてクリアした直後は、このエリアを色つきにして動きで目立たせる
- 迷路の一覧は2Dのミニマップ（[迷路の2D](#迷路の2dエディタとミニマップで共通)）で表示する。3Dはしょうさい画面とプレイ画面でだけ描く（タブレットでWebGLの描画を一つに限るため）

### もんだいのしょうさい / じぶんのめいろのしょうさい

- 見出し: もんだいは「{番号}. {名前}」（例:「4. <ruby>穴<rt>あな</rt></ruby>をうめよう」）、じぶんのめいろは迷路の名前。階数は3Dに「1F」「2F」が出るので見出しには出さない
- 見出しの左に「もどる」の矢印（ホームへ）
- 画面の大部分に迷路の3D（[迷路の3D](#迷路の3dしょうさいとプレイで共通)）。ロボットがスタートのマスに向きつきで立つ
- 3Dの下にボタンを横に並べる
  - もんだい: 「この<ruby>迷路<rt>めいろ</rt></ruby>で<ruby>遊<rt>あそ</rt></ruby>ぶ」（主）のみ
  - じぶんのめいろ: 「この<ruby>迷路<rt>めいろ</rt></ruby>で<ruby>遊<rt>あそ</rt></ruby>ぶ」（主）、「この<ruby>迷路<rt>めいろ</rt></ruby>を<ruby>変<rt>か</rt></ruby>える」「この<ruby>迷路<rt>めいろ</rt></ruby>を<ruby>消<rt>け</rt></ruby>す」（副）。消すは確認を出してから`DELETE /me/mazes/:mazeId`を呼び、ホームへ戻る
- 使うカードの種類やカードの枚数の上限は、この画面には出さない
- 迷路の読み方: チュートリアルは`packages/core`の`TUTORIALS`から番号で引き、`isTutorialUnlocked(no, clearedCount)`が偽ならホームへ移動する（通信しない）。じぶんのめいろは`GET /me/mazes`のキャッシュから`mazeId`で探す（[backend.md](backend.md#フロントエンド共通)）

### 迷路の3D（しょうさいとプレイで共通）

- 階は上に重ねて描く。上の階は少し透かして、下の階が見えるようにする
- 各階の横に「1F」「2F」の3Dの文字を置く。薄い青で弱く光らせる。常にカメラのほうを向かせる（難しければ厚みを持たせて回し続ける）
- ロボットは前身ProgPathの3Dモデル（`public/robot.gltf`）をそのまま使い、`START`のマスに`startDirection`の向きで立たせる
- 3Dは静止していて、児童が指で迷路の中心を軸に回す（自動で回し続けない。形を確かめる邪魔になり、動きを3か所に絞るルールにも反するため）。開いたときのカメラは斜め上から全階が見える角度。ズームは、迷路全体が画面に収まる距離を上限、迷路が画面の3分の1ほどになる距離を下限にする
- 光る表現は材質の発光（emissive）だけで行い、後処理（ブルーム）は入れない（タブレットの描画を重くしないため）

| マス           | 見た目                                                                                                                             |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `floor`        | コンクリートのタイル。枠線でマス目が分かるようにし、ひび割れの模様を入れる。他のマスの土台にもなる                                 |
| `wall`         | コンクリートの立方体。隣り合う壁との間に隙間を作らない                                                                             |
| `hole`         | ブラックホール。黒い円の上に、オレンジに光る輪を少し浮かせて重ねる                                                                 |
| `start`        | 床のタイルに、青く弱く光る「＜」の形の矢印。向きは`startDirection`。ロボットが動いた後も、最初の位置と向きが分かる                 |
| `goal`         | 緑の旗                                                                                                                             |
| `teleportUp`   | 赤い上向きの矢印。棒は線ではなく幅のある長方形。常に赤く弱く光る。常にカメラのほうを向かせる（難しければ厚みを持たせて回し続ける） |
| `teleportDown` | 青い下向きの矢印。色以外は上向きと同じ                                                                                             |
| `key`          | 金色のウォード錠の鍵の3D。持ち手は輪（トーラス）                                                                                   |

### プレイ（`/tutorials/$no/play`、`/mazes/$mazeId/play`）

一つのルートの中に「プログラムをつくる」と「ロボットを動かす」の二つの状態があり、同じ画面の中で切り替わります。

- 見出しはしょうさい画面と同じ（もんだいは「{番号}. {名前}」、じぶんのめいろは名前）。左に「もどる」の矢印
- 左半分: カメラ映像を背景にして、その上に迷路の3Dを重ねる（ARのように見せる。カメラはカードの読み取りと背景を兼ねる）
  - 3Dの見た目は[迷路の3D](#迷路の3dしょうさいとプレイで共通)と同じで、指で回せる
  - 回す中心は、ロボットが今いる階に置き続ける。ロボットが階を移ったら中心もその階に移す。ロボットがいない階は透明に近づける（児童がロボットの居場所を探さなくてよいようにする）
  - 右上に、ロボットが今いる階の2Dのミニマップ（[迷路の2D](#迷路の2dエディタとミニマップで共通)。ホームの一覧と同じ部品）を小さく重ね、その上にロボットの位置と向きを描く。動かしている間はターンごとに更新する
- 右半分: カードの並びと、下にボタン3つ

#### プログラムをつくる

- カードの並びは木構造をそのまま表示する。1枚が1つの命令で、くりかえしの中の命令は字下げし、エディタのインデントの線のような縦線を引く。くりかえしのカードの開閉ボタン（「＞」「∨」の形）を押すと中を開いたり閉じたりできる
- 開いているくりかえしの中の命令の下に、「くりかえし<ruby>終<rt>お</rt></ruby>わり」の行を出す（番号とゴミ箱はない。読み取った「くりかえし終わり」のカードに当たる）
- カードを押すと、そのカードの直後が差し込み位置になり、次に読み取ったカードからそこに入る。開いているくりかえしのカードはその中の先頭、「くりかえし終わり」の行はくりかえしの直後になる
- 差し込み位置は、カードとカードの間に引く太い青の線と「ここに<ruby>入<rt>はい</rt></ruby>る」の印で示す。最初は末尾
- カードの左端に番号（木を上から数えた順。1始まり）、右端にゴミ箱のアイコン。ゴミ箱でそのカードを消す（くりかえしを消すと中の命令も消える）
- くりかえしのカードは回数をボタンで表示し、押すとモーダルが開く。モーダルは「＜」「＞」で回数を2〜10に変え（2で「＜」、10で「＞」は押せない）、閉じるとカードに反映する。読み取った直後の回数は2
- 「くりかえし終わり」のカードを読み取ると、差し込み位置がくりかえしの中にあればその直後に出る。中になければ何も入れずに文言を出す（決まりは[domain.md](domain.md#カードの並びの編集児童の端末)）
- カードを読み取れたら、差し込み位置にカードが飛び込む動き＋短い効果音
- 同じカードを続けて使いたいときは、一度カメラから外して（1.5秒以上）からもう一度うつす（読み取りの重複防止は[domain.md](domain.md#カードの読み取り)）
- カードは6種類をKASANEで新しく印刷する（QRの中身は[domain.md](domain.md#命令カード)）
- KASANEのカードでないQRコードは無視する
- 枚数の上限（`validateProgram`）に当たったら、カードは入れずに理由の文言を出す
- ボタン
  - 「ロボットを<ruby>動<rt>うご</rt></ruby>かす」（主）: カードが0枚のときは押せない。押すと木構造をそのまま送る（カードを入れるたびに`validateProgram`で確かめているので、送る前にもう一度は確かめない。サーバーは必ず確かめる）
  - 「<ruby>最後<rt>さいご</rt></ruby>のカードを<ruby>消<rt>け</rt></ruby>す」「カードを<ruby>全部<rt>ぜんぶ</rt></ruby><ruby>消<rt>け</rt></ruby>す」（副）。<ruby>全部<rt>ぜんぶ</rt></ruby><ruby>消<rt>け</rt></ruby>すは確認を出す

#### ロボットを動かす

- サーバーから`CompileResult`が届くまでは、ロボットが準備する短い動きを見せる。届いたら`steps`を1ターン1秒でなぞる
- 動かしている間はカードの読み取りと差し込みができない
- 右側のカードの並びで、今のターンのカード（`path`から求める）を枠と色で示す。閉じているくりかえしの中なら自動で開く
- ボタンは同じ場所で役割が変わる
  - 「<ruby>最後<rt>さいご</rt></ruby>のカードを<ruby>消<rt>け</rt></ruby>す」→「<ruby>前<rt>まえ</rt></ruby>にもどる」、「カードを<ruby>全部<rt>ぜんぶ</rt></ruby><ruby>消<rt>け</rt></ruby>す」→「<ruby>次<rt>つぎ</rt></ruby>に<ruby>進<rt>すす</rt></ruby>む」。一時停止中だけ押せて、動いている間は押せない（灰色）
  - 「ロボットを<ruby>動<rt>うご</rt></ruby>かす」→「<ruby>一時<rt>いちじ</rt></ruby><ruby>停止<rt>ていし</rt></ruby>」。押すと止まって「ロボットを<ruby>動<rt>うご</rt></ruby>かす」に戻り、もう一度押すと続きから動く
  - 「前にもどる」は、`steps`から求めたそのターンの状態（位置・向き・埋めた穴・取った鍵）に戻す
- 1ターンの動き

| `Step`                 | 動き                                                                                                                             |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `move`                 | 前のマスへ滑らかに進む                                                                                                           |
| `turn`（右）           | 時間をかけて時計回りに90度回る                                                                                                   |
| `turn`（左）           | 時間をかけて反時計回りに90度回る                                                                                                 |
| `fill`                 | ロボットの前に青白く光る球が現れて大きくなり、前の穴が床に変わる（埋めた後は元からの床と同じ見た目）                             |
| `fillMiss`             | 何も見せない（このターンの時間も使わない）                                                                                       |
| `bump`（壁・迷路の外） | 動かずに止まり、結果の文言を出す                                                                                                 |
| `fall`                 | 穴のマスへ進んだ後、激しく回りながら縮んで見えなくなり、結果の文言を出す                                                         |
| `goal`                 | ゴールのマスへ進んだ後、その場で1回転してから跳ぶ（上がりは速く、下りは少しゆっくり）。鍵が残っていれば跳ばずに結果の文言を出す  |
| `tookKey`              | 鍵のマスへ進んだ後に一度止まり、鍵がロボットの真上へ上がって1回転して消える                                                      |
| `teleported`           | テレポートのマスへ進んだ後、縮んで消える。回す中心が隣の階へ移り、同じ行・列に現れる。移った先に鍵やゴールがあれば続けてその動き |

- 結果
  - ゴール: 「ゴールに<ruby>着<rt>つ</rt></ruby>いた！」、主ボタン「<ruby>次<rt>つぎ</rt></ruby>の<ruby>問題<rt>もんだい</rt></ruby>に<ruby>進<rt>すす</rt></ruby>む」（最後の問題なら「ホームにもどる」）。じぶんのめいろでは主ボタンは「ホームにもどる」
  - 失敗: 理由と次の行動を表示（[domain.md](domain.md#児童画面の文言)）。`bump`と`fall`のときだけ、止まったカードを赤くする（文言がカードの番号を使う失敗だけ。`tooLong`などは最後に実行したカードが原因ではないため）。主ボタン「プログラムを<ruby>直<rt>なお</rt></ruby>す」（カードの並びを残したまま「つくる」へ戻る）

- 動かしている途中で「つくる」へ戻る方法は置かない。戻れるのは結果が出て「プログラムを<ruby>直<rt>なお</rt></ruby>す」を押したときだけ（止めたいときは一時停止で止め、「次に進む」で結果まで進める）

### めいろをつくる / 変える（`/mazes/new`、`/mazes/$mazeId/edit`）

- 大きさ（一辺5・6・7）は新しく作るときだけ選び、後から変えない（途中で変えると外側の増減で迷路の形が崩れるため。変えたければ新しく作る）
- 新しく作るときの初期状態: 5×5、1階、すべてゆか、左上にスタート（`east`）、右下にゴール
- 左半分に迷路、右半分に道具のパレット、その下に主ボタン「できあがり」
- 左半分の上に「1<ruby>階<rt>かい</rt></ruby>」「2<ruby>階<rt>かい</rt></ruby>」「3<ruby>階<rt>かい</rt></ruby>」の切り替えボタンを横に並べる。今編集している階は青の塗りつぶし、他は枠だけにする。隣に階を足す・減らすボタン
- その下に、今見ている階のマス目を2Dで表示する（3Dにしないのは、タップで正確に塗るため）。マスの見た目は[迷路の2D](#迷路の2dエディタとミニマップで共通)
- 道具: ゆか / かべ / <ruby>穴<rt>あな</rt></ruby> / スタート / ゴール / <ruby>上<rt>うえ</rt></ruby>へテレポート / <ruby>下<rt>した</rt></ruby>へテレポート / かぎ（壁・床・鍵は小学校で習わない漢字なのでひらがな）。選んでいる道具は枠と色で示す。アイコンは2Dのマスと同じ
- 大きさや置き方の決まりは画面に書かない。置けないときに理由を文言で出すだけにする
- マスをタップするとその道具で塗る。置けないときは塗らず、マス目の下に3秒ほど理由の文言を出す（モーダルにしない。編集中に何度も起きるので、そのたびに閉じさせない）。決まりは[domain.md](domain.md#迷路の編集児童の端末)、文言は下の表
- スタートのマスをもう一度タップすると、ロボットの向きが右回りに変わる（矢印で表示）
- 階を足す（最大3階。新しい階はすべてゆか）、いちばん上の階を減らす。減らせないときも同じ場所に理由の文言を出す
- 上部に「<ruby>迷路<rt>めいろ</rt></ruby>の<ruby>名前<rt>なまえ</rt></ruby>」の入力欄（1〜20文字、初期値「めいろ1」など。初期値は保存される文字列なのでルビなし）
- 編集中の迷路は端末のメモリだけに持ち、「できあがり」を押すまでサーバーへ送らない。途中で画面を離れようとしたら確認のモーダルを出す。文言は「まだ<ruby>迷路<rt>めいろ</rt></ruby>ができあがっていないよ。やめると、<ruby>今<rt>いま</rt></ruby>の<ruby>形<rt>かたち</rt></ruby>は<ruby>消<rt>き</rt></ruby>えるよ」、ボタンは左に「<ruby>作<rt>つく</rt></ruby>るのをやめる」（枠だけ）、右に「<ruby>作<rt>つく</rt></ruby>り<ruby>続<rt>つづ</rt></ruby>ける」（青の塗りつぶし）。安全な側を強調し、押した結果が分かる言葉にする（「はい」「いいえ」「離れる」「離れない」のような、読まないと意味が決まらない対の言葉は使わない）
- 主ボタン「できあがり」: 保存（`POST /me/mazes`か`PUT /me/mazes/:mazeId`）してしょうさい画面へ移動する

### 迷路の2D（エディタとミニマップで共通）

## 教師の画面

### ホーム（`/`）

- 主ボタン「授業を始める」: 授業を作り、QRコードを見せる画面へ移動する
- 「開いている授業」の一覧: 「11月5日10:40に始めた授業」「参加している児童: 6」。押すと進み具合へ移動する
- 一覧が空のとき: 「開いている授業はありません。「授業を始める」を押すと、児童が参加するためのQRコードが表示されます」
- 授業は「授業を終える」を押すと終わる。押し忘れたときは、作成から5時間で自動的に終わる（午前の4コマと休み時間に、1時間の余裕を足した長さ）。終わった授業は一覧から消える

### QRコードを見せる（`/lessons/$lessonId/invite`）

- プロジェクターや大型テレビに映す前提で、QRコードを画面いっぱいに表示する
- QRの中身は`{STUDENT_ORIGIN}/join?lesson={lessonId}`。`lessonId`はURLのパスから、`STUDENT_ORIGIN`は教師用アプリのビルド時の環境変数から取り、画面側だけで作る（サーバーは呼ばない）
- 「児童のタブレットのカメラで、このQRコードを読み取ってください」
- この画面でサーバーと通信するのは教師用のSSE（`GET /lessons/:lessonId/events`）だけ
  - 参加した児童の数は、`snapshot`の全員と`student`で届いた児童を`studentId`をキーにした`Map`に入れ、その件数で表す。増えたら数字が弾む動き
  - 接続が`404`か`410`で始まらないとき、または`ended`が届いたときは「この授業は終わっています」と表示し、ホームへ戻るボタンを出す
- 主ボタン「進み具合を見る」
- 5秒以上サーバーとつながらないときは、上部に回る印と「つながっていません。つなぎ直しています」の帯を出し、つながったら消す（[backend.md](backend.md#再接続)）

### 進み具合（`/lessons/$lessonId`）

児童を参加順にカードで並べます。開いたときに全児童の状態をまとめて受け取り、その後はSSEで変化のあった児童だけを受け取ります。届いた児童の行は、その児童の状態全体で上書きします。

| 項目           | 表示                                                                                              |
| -------------- | ------------------------------------------------------------------------------------------------- |
| 名前           | 大きく                                                                                            |
| 進み           | 「チュートリアル3/7」と進捗バー。すべてクリアしたら星のアイコン＋「チュートリアルをすべてクリア」 |
| 今の問題の結果 | アイコン＋色＋文言で「まだ送っていない」「成功」「失敗」のどれか                                  |

「今の問題」と「結果」の決め方は[backend.md](backend.md#教師に見せる状態の求め方)を参照してください。

- 画面上部に「QRコードをもう一度表示する」（副）と「授業を終える」（副、確認ダイアログあり）
- 5秒以上サーバーとつながらないときは、上部に回る印と「つながっていません。つなぎ直しています」の帯を出し、つながったら消す（[backend.md](backend.md#再接続)）
- 授業を終えると、教師の画面はホームへ戻り、全児童の画面はすぐ`/ended`へ移る
- 終わった授業を開こうとしたとき（作成から5時間たった授業など）は「この授業は終わっています」と表示し、ホームへ戻るボタンを出す

## うまく動かなかったときの受け止め（エラーバウンダリー）

- 児童: `/join`と`/ended`以外を包むパスなしレイアウトに一つ置く。描画中の例外を受けたら「うまく<ruby>動<rt>うご</rt></ruby>かなかったよ。もう<ruby>一度<rt>いちど</rt></ruby><ruby>開<rt>ひら</rt></ruby>いてね」と主ボタン「もう<ruby>一度<rt>いちど</rt></ruby><ruby>開<rt>ひら</rt></ruby>く」（ページを読み込み直す）を出す。ホームへ戻す形にしないのは、ホーム自体で起きたときに同じ受け止めが繰り返されるため。トークンは`localStorage`にあるので、読み込み直しても同じ児童として続けられる
- 教師: ルートに一つ置く。「問題が起きました。ページを読み込み直してください」と主ボタン「読み込み直す」
- 想定内の失敗（置けない・通信できない・授業が終わった）はここに来ない。それぞれの場所で文言を出す（各画面の節）
