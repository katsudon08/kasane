# なぜKASANEを作るのか

KASANEは、QRカードで命令を組み、ロボットを動かす小学校向けのプログラミング教材です。児童が一人で考えたことを友達との話し合いに持ち寄り、その結果を踏まえて自分の考えを直す。その学習の流れを、授業の中で作りやすくするために開発しています。

## 国が示している方向

現行の小学校学習指導要領は、児童がプログラミングを体験し、コンピュータに意図した処理をさせるための論理的思考力を育む学習活動を、計画的に行うよう求めています。また、中央教育審議会の答申は、一人で学んだ成果を協働に生かし、協働で得たものを再び一人の学びに戻すことを重視しています。

次期学習指導要領に向けた文部科学省の検討資料では、プログラムを正しく作ることに加え、順次・分岐・反復を課題解決に使う方向が示されています。これは現在検討されている方向であり、現行の学習指導要領とは区別して捉えています。

詳しくは[国の方針と資料](national-policy-documents.md)を参照してください。

## 小学校で起きていること

端末の整備は進みましたが、プログラミングに充てられる時間は多くありません。文部科学省の令和4年度調査では、第5学年の年間授業時数は平均5.8時間、第6学年は6.7時間でした（いずれも年度計画）。また、令和3年度実施の情報活用能力調査では、第5学年のうち、プログラムの不具合から修正箇所を見つける段階以上に達した児童は8.7%でした。

導入先の教育委員会は、国が示す方向とKASANEの取組に賛同しています。一方、教師には「なぜ取り組むのか」という疑問が多く、ICT操作にも大きな支援が必要だと聞いています。授業で使う意義を伝え、教師が取り組める条件を整えることも課題です。

Scratchなどの教材はありますが、画面操作に慣れていない児童には操作自体が負担になり得ます。また、児童が予測を立て、実行結果の理由を話し合ってから直すかどうかは、教材の使い方や教師の働きかけに左右されます。KASANEの前身であるProgPathは、QRカードで命令を組むことで画面操作を減らしましたが、一人で考える時間と話し合う時間を授業の中でつなぐ仕組みはありませんでした。

全国の調査と導入先の状況は[小学校の現状](elementary-schools-status.md)、既存教材とProgPathについては[教材の検討](teaching-materials-review.md)に記しています。

## KASANEでできるようにすること

KASANEにはProgPathと同じように一つの端末を複数人で使用する**シングルモード**と新たに追加した**ペアモード**が存在します。

どちらのモードでも、児童は用意されたチュートリアルを順番に解き、すべて終えた後に自分で問題を作ります。教師が授業ごとに迷路を選ぶ流れではありません。

ペアモードでは、二人がそれぞれ相手のロボットの動きを予測し、自分のロボットの動きを考えます。その後、互いの考えを説明して二台を同時に動かし、予測と実際の違いを手がかりに話し合います。うまくいかなければ、各自がもう一度予測とプログラムを作り直します。二人がそろうまで次の段階に進まない仕組みによって、一人で考える時間と協働する時間を授業の流れに組み込みます。

教師には、児童やペアの進行状況を一覧で示します。誰がどの段階で止まっているかを見て、支援する相手を判断できます。前身のProgPathと同じ進め方も、シングルモードとして残します。

KASANEが支えられるのは、こうした活動に取り組む機会と順序です。児童が実際にどう考え、何を身に付けたかは、授業での観察や別途行う評価で確かめる必要があります。
