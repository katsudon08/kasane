# 仕様書

## 1. 概要説明

本サービスは別リポジトリである[ProgPath](https://github.com/katsudon08/prog-path)の後継にあたります。

児童はそれぞれが自分のロボットを操作し、二人一組で迷路を攻略します。
教師は各児童ペアの状況を確認し、適切に支援を行います。

迷路には**各児童専用のゴール**が設置されていて、二人がゴールしたらクリアです。
片方だけがゴールしてもクリアにはなりません。

児童がプログラムを作成してから実際に迷路をクリアするまでのフローを以下に明示し、本ドキュメント内の基準として扱います。

### 進行フロー

> #### 予測フェーズ
このフェーズでは児童は**話し合いを行うことができません**。

相手のロボットの動きを予測してプログラムを作成します。
入力手段は**QRコード**を使用します。

この時点では**自分のロボットのプログラムは作成しません**。

プログラム作成後、相手のロボット単体で動作確認を行うことができます。
ただし、迷路内に自分のロボットはまだ存在しないため、迷路をゴールすることはできません。

予測を確定させるとプログラムがロックされて**バージョン1**として保存され、相手に通知されます。

**予測を確定した後でも動作確認は行うことができます。**

二人が予測を確定させることで次の[実装フェーズ]()に進みます。

↓

> #### 実装フェーズ
このフェーズも児童は**話し合いを行うことができません**。

自分のロボットのプログラムを作成します。
入力手段は先ほど同様**QRコード**を使用します。

[予測フェーズ]()でロックした相手のロボットと自分のロボットを同時に走らせて、何度でも検証することが可能です。

検証をする過程で予測が間違っていると気付いた場合、[予測フェーズ]()で作成したプログラムを更新することができます。
更新したプログラムは検証するたびに変更がロックされて、**バージョン2**、**バージョン3**のように保存されます。

自分のプログラムを確定させると変更がロックされ、相手を予測するプログラムもロックされたのちに相手に通知されます。
ここでロックされたバージョンが[実行フェーズ]()で使用されます。
ただし、作成した**プログラムは共有されません**。

双方が確定すると次の[説明フェーズ]()へ遷移します。

↓

> #### 説明フェーズ
このフェーズから児童は**話し合うことができます**。

先ほども記述してあるように[実装フェーズ]()までに作成しているプログラムは変更不可となっていて、プログラムは共有されません。

児童は自分がどのように動くつもりなのか、相手の動きをどのように予測したのかを自分の口で言語化してペアの児童へと説明します。

説明を聞いて予測の誤りに気づいても、**プログラムの修正は行えません**。

↓

> #### 実行フェーズ
このフェーズでは児童は**話し合いを行うことができません**。
意図としては、各児童が自分の目でロボットの動きの差分を確認するためです。

**ゴースト世界**と**実体世界**を重ねて実行します。
画面には自分のゴースト、自分の実体、相手のゴースト、相手の実体の4台のロボットが重なって表示されます。

差分は児童ごとに異なるため、**二人が見ている画面の内容は異なります**。

二人ともゴールに到達した場合は[振り返りフェーズ]()へ、それ以外の場合は[議論フェーズ]()に遷移します。(**手数超過も含まれます**)

↓

> #### 議論フェーズ
このフェーズから児童は**話し合うことができます**。

[実行フェーズ]()で各児童が差分を把握した状態で開始するため、どちらかだけが考えて一方はそれに従うという状況が起こりにくくなっています。

ここでもプログラムは開示されません。
**相手が何をどう考えていたのかは、口頭で聞くことでしか得られません**。

差分を手掛かりに原因を考え、改善の方針を話し合います。
ここで決めるのはあくまでも方針であって、プログラムそのものではありません。

方針が決定したら、[予測フェーズ]()へ戻って次のラウンドを開始します。

↓

> #### 振り返りフェーズ
このフェーズは二人ともゴールした場合にのみ発生し、児童は**話し合うことができません**。

各児童の画面に、自分が予測した相手のプログラムと、相手の実際のプログラムを並べて表示します。

同じ動きを別の書き方で実現している箇所があれば、そこに児童が気づくことができます。
これにより、協働によって得られたものを**自分自身の理解へ戻します**。

---

これまでのフローの中で話し合いができるフェーズとできないフェーズが交互に配置されていたのは、**自分の考えを児童にきちんと持たせてからペア間での話し合いを行わせるため**です。

また、変更不可のポイントがいくつか設置されているのは**児童が自分で考えた思考を履歴として積み重ねることを目的**としています。

---

## 2. プログラムと予測

児童一人につき二つのプログラムを作成します。
相手の動きを予測する**予測プログラム**と、自分のロボットを動かす**自分のプログラム**です。
どちらもQRコードで作成します。

予測をプログラムとして組ませることで、相手のロボットがどう動くのかを実際に**分解・手順化**して考える必要が生じます。
また児童はQRコードでプログラムを組む操作を既に習得しているため、**予測のために新しい入力方法を覚える必要がありません**。

### 予測を先に作成する理由

一つ目は、**児童同士が事前に計画を共有してしまうことを構造的に防ぐため**です。

自分のプログラムを先に作成すると、その時点で共有できる計画が手元にあるため、話してしまえば予測は不要になります。
予測を先に行わせれば、その時点ではどちらもまだ何も決めていないため、**共有すべき情報がそもそも存在しません**。

ただしこれで完全に防げるわけではありません。
「たぶん左から行く」といった確定前の意図は口にできます。
しかしそれは確定したプログラムではないため、**漏れる情報は不正確になります**。

二つ目は、**思考の順序として正しいため**です。

予測を先に置くことで「相手はこう動くと思う、だから自分はこうする」という因果になります。
自分の計画を先に立てると、相手の予測は後から辻褄を合わせる対象になってしまいます。

この順序により、予測は事後に評価されるものではなく、**自分の計画を立てるための前提条件**になります。

### 却下した案

- **自分のプログラムを先に作成する** : 確定済みの計画が手元に生まれるため、話せば全て漏れます。
- **予測を最後まで変更不可にする** : 間違いに気づいても直せず、ゴースト世界が意味を成しません。

## 3. 世界と差分

### 三つの世界

世界は二種類ですが、ゴースト世界は児童ごとに存在するため、ペア全体では**三つの世界**が生まれます。

| 世界 | 所有 | ロボットA | ロボットB |
| --- | --- | --- | --- |
| 実体世界 | ペアで共有 | Aの実際のプログラム | Bの実際のプログラム |
| Aのゴースト世界 | A | Aの実際のプログラム | **AがBを予測したプログラム** |
| Bのゴースト世界 | B | **BがAを予測したプログラム** | Bの実際のプログラム |

各世界にロボットが二台いるため、軌跡はペア全体で**六本**になります。
ただし、各児童の画面に表示されるのは実体世界の二本と自分のゴースト世界の二本を合わせた**四本**です。

AはBのゴースト世界を見ません。
BがどのようにAを予測したかはB自身の問題であり、**Aが行動に移せる情報ではない**ためです。

```
ゴースト世界 = simulate(自分のプログラム, 自分が予測した相手プログラム, 実行規則)
実体世界     = simulate(自分のプログラム, 相手の実際のプログラム,     実行規則)
```

**ゴーストはロボットの種類ではなく世界の名前です。**
ゴースト世界にいる二台はどちらもゴーストであり、実体世界にいる二台はどちらも実体です。

### 差分は二種類

| 種類 | 比較対象 | 測るもの | 児童にとっての意味 |
| --- | --- | --- | --- |
| **原因** | 相手のゴーストと相手の実体 | 他者理解の正確さ | 相手を読み違えた |
| **結果** | 自分のゴーストと自分の実体 | 読み違えが自分に及ぼした影響 | その代償を払った |

差分は**ペアのものではなく児童個人のもの**です。
一度の実行からAは差分ゼロ、Bは差分ありという状態が起こり得ます。

### 比較基準

コマンド列ではなく、**一手ごとの盤面状態の系列**を比較します。

`ループ(前進) × 4` と `前進, 前進, 前進, 前進` は動きが同一です。
コマンド列で比較すると、**抽象化ができている児童ほど外れと判定されてしまいます**。
児童が理解すべきなのは相手のロボットの動きであって、記述の仕方ではありません。

### 提示方法

児童には**数値を表示しません**。
表示するのは、最初にずれたターンへのジャンプと、その前後を確認するための再生です。

原因を考える手掛かりは「どこで」であって「どれくらい」ではありません。
数値を出すと、スコアを下げることが目的になり、原因を考えなくなります。

教師には不一致ターン数（または不一致率）を、**原因と結果で別々に**表示します。

### 保存

指標ではなく、**盤面状態の系列そのものを保存**します。
系列さえ残っていれば、指標を後から計算できます。

### 却下した案

- **最終位置の距離を差分の大きさとする** : 途中を全て捨てるため、ずれ続けて最後だけ一致した場合を完璧と判定してしまいます。
- **軌跡を線として描いて差分を示す** : 軌跡は空間、ずれは時間。待機が一ターン入っただけのずれが映らなくなります。
- **コマンド列を比較する** : 同じ動きを別の書き方で実現した児童を外れと判定してしまいます。

## 4. 迷路の仕掛けと相互依存

| 仕掛け | 規則 | 生まれる判断 |
| --- | --- | --- |
| **ボタン** | 自分しか押せない。押すと**相手**の鍵が解放される。自分には直接の得がない | **順序**（自分の仕事と相手の仕事、どちらを先にやるか） |
| **鍵** | 相手がボタンを押した後でないと取れない。自分のゴールの解錠に必要でnターン後に消滅 | **タイミング**（何手目に合わせるか） |
| **穴** | 埋めると床になる（ProgPathの`穴をうめる`を流用） | **分担**（誰が埋めるか） |

### なぜ二人でやる必要があるのか

ボタンは自分に何の得もないため、利己的に考えれば押す理由がありません。
しかし**二人とも押さなければ、鍵が一つも出現せず両方が失敗します**。

児童は「相手を助けなさい」と言われて助けるのではなく、**助けないと自分が損をするから助けます**。
そしてその因果を、児童自身が失敗から導出します。

この構造は、他者理解を**道徳の問題ではなく論理の問題**に変換しています。

### 干渉の分類

**負の干渉**は排他マスによる進路妨害です。読み違えると損をするという圧力を生みます。

**正の干渉**はボタン・鍵・穴による依存です。相手がいなければ達成できないという関係を生みます。

負の干渉だけでは相手が障害物にしかならず、協働的な学びになりません。
正の干渉によって初めて、**相手の存在が自分の目的達成の前提条件**になります。

### 今後の設計を縛る規範

- **共有は相互作用ではありません。** 二人が同じ壁を見ているだけでは、同じ問題を別々に解いているに過ぎず、判断は増えません。判断が増えるのは、**一方の行動によって他方の前提が変わる場合だけ**です。
- **依存を縦に入れ子にしてはいけません。** 対称にすると循環参照で始動できず、非対称にすると先手と後手が生まれ、一方だけが考えて他方が従う状態を招きます。現行案が機能しているのは**起点が二つある**ためです。

### 却下した案

- **穴に所有者を設ける** : ボタンのコピーとなり、残る判断が「いつ」だけになります。
- **依存を入れ子にする（自分のボタン→相手のボタン→自分の鍵）** : 今後の設計を縛る規範に反しています。

## 5. 実行規則と手数予算

最上位の制約は**決定性**です。同じ入力なら必ず同じ出力になり、ランダム要素は一切使いません。
実行結果が揺らげば、予測が外れた原因が児童の思考の誤りなのかシステムの揺らぎなのか区別できず、**学習そのものが成立しません**。

| # | 規則 |
| --- | --- |
| 1 | **同時に一ターンずつ**進む（交互ではない） |
| 2 | 相手が今いるマスには進めない（**排他マス**） |
| 3 | 両者が同じマスを狙ったら、**両方その場に留まる** |
| 4 | ゴールに到達したロボットは**盤面から消える** |
| 5 | 待機コマンドは用意しない |

### 手数予算

制限時間（ターン上限）を設け、**最短手数ぎりぎりまで余裕を削ります**。

これにより二つの抜け道が同時に塞がれます。

- **待つ戦略** : 長く待てば必ず鍵は手に入るが、予算超過で失敗する
- **急ぐ戦略** : 何も考えず最速で動くと鍵のマスに早く着きすぎ、往復で予算を失う

判定基準は次の一文です。

> **予測を組んだ児童が、組まなかった児童より確実に得をするか。**

この不等式が成り立たなければ、本サービスは予測してもしなくても同じゲームになります。
児童は正直なので、必ず楽な方を選びます。

### 却下した案

- **交互に一手ずつ進める** : 非対称性を実行規則の最下層に埋め込むことになります。
- **待機コマンドを用意しないことで待機を封じる** : 回転の組み合わせで合成できるため禁止になりません。
